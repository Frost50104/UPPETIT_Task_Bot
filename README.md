# UPPETIT Task Bot

Телеграм-бот для постановки и контроля задач сотрудникам по группам. Бот отправляет задачи в личные сообщения сотрудникам, принимает фото‑отчёты о выполнении и пересылает их в контрольный чат, где администраторы подтверждают или отклоняют выполнение. Поддерживает ежедневную, еженедельную и ежемесячную авторассылку, планирование задач, напоминания и ведение логов.


## Возможности
- Управление сотрудниками по группам (добавление/удаление, список пользователей)
- Управление администраторами
- Постановка задач:
  - группам
  - отдельным сотрудникам
  - всем сразу
- Контроль выполнения: фото‑отчёты в контрольный чат с подтверждением/отклонением
- Напоминания невыполнившим задачу
- Авторассылка задач (ежедневная/еженедельная/ежемесячная) и просмотр расписания
- Планирование задач на выбранные дату/время
- Просмотр и очистка списков задач
- Ведение логов и журналов отправки

## Что нового (2025-08-26)
- Устойчивость к сетевым таймаутам Telegram API: бот запускает polling в бесконечном цикле с экспоненциальной паузой и увеличенным long polling таймаутом. Кратковременные проблемы сети больше не приводят к длительному простою.
- Автоматический перезапуск: unit-файл systemd настроен на Restart=always с задержкой 5 секунд и зависимостью от network-online.target.
- Меньше дублей в логах: добавлено подавление идентичных строк в пределах 2 секунд и лог «Бот был перезапущен» записывается один раз на запуск.

## Требования
- Python 3.10+
- Аккаунт Telegram и созданный бот через @BotFather (токен)
- Доступ к контрольному чату (supergroup ID, начинается с -100...)


## Установка
1) Клонируйте проект
```
git clone <repo-url>
cd UPPETIT_Task_Bot
```

2) Создайте и активируйте виртуальное окружение
```
python3 -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
```

3) Установите зависимости
```
pip install -r requirements.txt
```


## Настройка
Основные настройки находятся в файле `config.py`:

- `TOKEN` — токен вашего Telegram‑бота от @BotFather.
- `ADMIN_ID` — список ID администраторов (числа). Как узнать свой ID — командой `/my_id` в боте.
- `performers_list_X` — списки пользователей (ID сотрудников) по группам.
- `performers` — словарь «название группы → список исполнителей» (используется для отображения в интерфейсе бота).
- `daily_tasks`, `weekly_tasks`, `monthly_tasks` — тексты задач для авторассылки по группам.
- `performers_by_group` — соответствие `task_group_X → список ID` (используется авторассылкой).
- `status_monthly`, `monthly_schedule` — включение и расписание месячной рассылки.
- `status_weekly`, `weekly_schedule` — включение и расписание недельной рассылки.
- `status_work_time`, `work_time` — включение и расписание ежедневной рассылки.
- `control_chat_id` — ID контрольного чата (для супергруппы начинается с -100...).

Замечания по безопасности:
- Никогда не публикуйте реальный `TOKEN` в открытом репозитории.
- Рекомендуется хранить токен в переменной окружения и подставлять в `config.py` (при необходимости модифицируйте код под это), либо держать `config.py` вне контроля версий.


## Запуск
Запуск в активированном виртуальном окружении:
```
python main.py
```
Примечания:
- Бот использует устойчивый к ошибкам цикл polling с экспоненциальной задержкой (5 → 10 → 20 → 40 → 60 сек) и увеличенным long polling таймаутом. При сетевых таймаутах он автоматически пытается продолжить работу.
- В лог пишется одна строка «СИСТЕМА - Бот был перезапущен» на каждую сессию polling.

Бот должен быть добавлен в нужные чаты и иметь права для пересылки сообщений/медиа в контрольный чат.


## Авторассылка и планирование
Бот поддерживает автоматическую отправку задач, если включены соответствующие флаги в `config.py`:
- Ежедневная: `status_work_time = 'on'`, время в `work_time = ['HH:MM', ...]`
- Еженедельная: `status_weekly = 'on'`, расписание в `weekly_schedule = [('friday', '14:31'), ...]`
- Ежемесячная: `status_monthly = 'on'`, расписание в `monthly_schedule = [(2, '14:35'), ...]` (число месяца, время)

Также доступно планирование задач через команду `/planning` — просмотр, добавление, редактирование, удаление задач, которые будут отправлены автоматически в выбранную дату/время.


## Список команд (для администраторов)
Ниже приведены основные команды, соответствующие тексту помощи бота:

1) Управление пользователями
- `/bot_users` — список сотрудников по группам
- `/add_user` — добавить сотрудника в группу
- `/delete_user` — удалить сотрудника из группы
- `/my_id` — узнать свой ID

2) Управление администраторами
- `/admins` — список администраторов
- `/add_admin` — добавить администратора
- `/delete_admin` — удалить администратора

3) Управление группами
- `/set_group_name` — переименовать группу
- `/set_task_group` — изменить текст заданий для авторассылки по группам

4) Постановка задач
- `/group_task` — задача одной/нескольким группам
- `/user_task` — задача отдельному сотруднику/нескольким сотрудникам
- `/all_task` — задача всем сотрудникам
- `/tasks_list` — активные задачи с группировкой и статусом
- `/arbeiten` — напоминание тем, кто не выполнил
- `/clear_all_tasks_list` — удалить все задачи
- `/clear_tasks_list` — удалить только выполненные

5) Автоматическая рассылка
- Ежедневная:
  - `/auto_send` — включить/выключить
  - `/set_time` — настроить время
- Еженедельная:
  - `/auto_send_weekly` — включить/выключить
  - `/set_day` — настроить день недели и время
- Ежемесячная:
  - `/auto_send_monthly` — включить/выключить
  - `/set_month` — настроить дату и время
- Прочее:
  - `/show_schedule` — показать текущие настройки всех авторассылок

6) Планирование задач
- `/planning` — управление запланированными задачами (просмотр/добавление/редактирование/удаление)


## Файлы данных и логи
- `planned_tasks.json` — запланированные задачи
- `assigned_tasks.json` — выданные задачи и их статусы
- `sent_log.json` — журнал отправок
- `task_log.txt` — лог задач
- `all_logs.txt` — объединённый лог активности. Встроено подавление дубликатов лог‑строк в пределах 2 секунд (например, повторные одинаковые события подряд не засоряют журнал). Сообщение о перезапуске бота пишется один раз на запуск.
- `user_cache.json` — кэш пользователей

Очистка логов доступна через команды `/clear_log`, `/clear_all_logs` (если предусмотрены в хэндлерах) и соответствующие команды для задач. Просмотреть журнал можно командой `/all_logs` или `/show_log`.


## Развертывание через systemd (Linux)
В репозитории есть пример `bot.service`. Рекомендуемая конфигурация unit‑файла (уже отражена в файле проекта):
```
[Unit]
Description=Python Bot
After=network-online.target
Wants=network-online.target

[Service]
User=petr
Environment=PYTHONUNBUFFERED=1
WorkingDirectory=/home/petr/projects/UPPETIT_Task_Bot
ExecStart=/home/petr/projects/UPPETIT_Task_Bot/venv/bin/python main.py
Restart=always
RestartSec=5
StartLimitIntervalSec=300
StartLimitBurst=30

[Install]
WantedBy=multi-user.target
```
Шаги установки/обновления:
1) Отредактируйте пути под вашу систему в `bot.service`.
2) Скопируйте unit‑файл:
```
sudo cp bot.service /etc/systemd/system/bot.service
```
3) Примените изменения и запустите сервис:
```
sudo systemctl daemon-reload
sudo systemctl enable --now bot.service
```
4) При обновлении unit‑файла повторите:
```
sudo systemctl daemon-reload && sudo systemctl restart bot.service
```
5) Просмотр логов сервиса:
```
sudo journalctl -u bot.service -f
```


## Советы и диагностика
- Сетевые таймауты (ReadTimeout): бот автоматически делает повторные попытки с увеличением паузы и продолжит работу без ручного вмешательства. Для развёртывания как сервиса используйте systemd (см. выше).
- Ошибка 403 Forbidden при рассылке: означает, что пользователь заблокировал бота. Такие случаи логируются и не приводят к остановке работы; можно исключать этих пользователей из рассылок.
- Проверьте, что `TOKEN` корректен, бот запущен и «видит» интернет.
- Убедитесь, что `control_chat_id` верный (для супергруппы начинается с -100...).
- Если авторассылка не срабатывает, проверьте статус и расписание в `config.py` и командой `/show_schedule`.
- Используйте `/my_id` для получения ID и корректной настройки списков исполнителей и админов.
